# Agent 声明「会话未完成」— 需求

## 背景

`native-agent-completion-boundary` 只能识别 **CLI 自己登记过** 的后台工作（Claude Stop 钩子的
`background_tasks` / `session_crons`）。以下情况 Chill Vibe 仍把回合当成「整件事做完了」：

- Agent 用 `Start-Process` / `nohup` / 独立终端拉起的构建、打包、长测试、开发服务器；
- 等远端 CI、等发布、等别的会话产出；
- Codex、Gemini 根本没有原生后台边界信号。

误判会触发链式后果：完成音效 / 闪窗 / 呼吸光、计时唤醒放行等它的卡、自动化看板把卡挪到完成道、
Auto-Urge 鞭策、「全部 Agent 完成」提示音、超管 await_sessions 提前返回。

用户 2026-11-27 明确提出：在 Chill Vibe 里定一个约定，让 agent 给会话打标记，UI 与内部触发都能识别
「这个会话整体还没做完」。

## 需求

1. 三家 provider（Claude / Codex / Gemini）的系统提示都注入同一条约定：回合结束时如果自己起的工作
   仍在后台跑、需要回头检查，就在最终回复末尾写一个标记，包含「在等什么」与「预计多少分钟后回来查看」。
2. 标记只在**本回合最后一条 assistant 正文**里生效；在正文里渲染时隐藏，不打扰阅读。
3. 带标记的回合按「后台未完成」结算，与原生 `background-pending` 同一套门控：不响完成音、不闪窗、
   不亮完成光、不追加运行时长、不放行等它的计时唤醒、不触发 Auto-Urge、不算「全部完成」、
   看板不挪道、超管镜像显示仍忙。延后消息照旧放行（与原生 pending 一致）。
4. 有上界：分钟数夹在 1–240，缺省 30。到点时若卡仍闲着、标记仍在，Chill Vibe 自动给该会话发一条
   「自查」消息，让 agent 检查后台进度：完成了就正常汇报（不再带标记 → 正常完成），没完成就再带标记。
5. 连续自动自查有次数上限（8 次）；超过即清除标记、在卡里留一条说明，不再自动发。
6. UI：
   - tab 与收起 chip 把「agent 声明未完成」当运行态（呼吸），因为它有上界，不会粘住；
   - 输入框上方显示一条状态：在等什么、几点自查，提供「立即自查」「标为已完成」两个按钮。
7. 用户手动发送新消息、手动停止、终态错误、换模型 / 重置会话时清除标记；手动「标为已完成」只清标记，
   不补发完成回调。
8. 邻卡（计时唤醒的「其他 Agent」判据）带 agent 声明标记时算忙；原生后台 shell 仍按原口径。
9. 标记字段只是运行时状态，跟随 `backgroundWorkPending` 一起清；`backgroundWorkPending` 变成非 true
   时声明字段必然被清掉，不允许单独残留。

## 非目标

- 不靠回复文本「猜」是否在等；只认显式标记。
- 不改原生 Claude Stop 钩子判定。
- 不新增 MCP 工具。

## 验收

- 一个 Codex 回合以标记结尾：卡片 idle、不响完成音、tab 呼吸、输入框上方显示等待原因；
  等它的计时唤醒不放行。
- 到点后自动发出自查消息；agent 回复不带标记 → 正常完成一次（音效、计时唤醒放行）。
- 连续 8 次自查仍带标记 → 标记清除并留说明。
- 用户手动发消息后，新回合不带标记 → 状态条消失。
