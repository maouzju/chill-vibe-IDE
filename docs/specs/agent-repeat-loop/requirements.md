# Agent 循环重复 — 需求

## 背景

用户有一类需要反复从同一条起始提示重新执行的 Agent 任务。当前只能手动新建 Tab、复制首条提示并再次发送，长时间重复时容易漏操作，也无法在每轮结束后自动开始下一轮。

## 需求

1. 设置页“实用”区域新增“循环重复功能”总开关，**默认关闭**；旧状态缺少字段时必须安全补为关闭。
2. 只有总开关开启时，普通 Codex / Claude Agent 聊天的输入框右侧设置菜单才显示“循环重复”勾选项；工具卡不显示，聊天正文顶部不再放置可操作的重复开关。
3. 勾选状态属于当前聊天卡，可持久化。总开关关闭时隐藏并停止触发，但不删除各聊天原有勾选状态，重新开启后可继续使用。
4. 用户可在任务运行期间取消勾选；终态到达时以最新状态为准，取消后不得再创建下一轮。
5. 仅在原生 Agent 的**最终成功完成边界**触发下一轮：
   - Claude `background-pending` 中间暂停不得触发；
   - 手动停止、用户中断、错误、卡片关闭不得触发；
   - Codex 子 Agent 完成不得越过现有根线程完成边界触发。
6. 触发时读取该聊天中最早一条非空的用户文本提示，新建并激活同一 Pane 内的 Agent Tab，自动发送该提示并立即开始。
7. 新 Tab 必须是全新会话，不继承 provider 原生 session 或历史消息；但要继承来源 Agent 的 provider、模型、推理强度、思考开关和计划模式，并继续保持“循环重复”勾选，从而形成连续循环。
8. 自动重放只复用文本提示，不复制首轮附件。若聊天内没有可复用的非空用户文本，则本轮结束后不新建 Tab。
9. 当前卡若仍有延后发送队列或计划唤醒批次，必须先完成这些已安排的续写；等最后一次正常完成且队列已清空后，才进入循环下一轮。
10. “循环重复”优先于当前卡及全局“自动鞭策”：勾选循环时不得同时在旧 Tab 内自动发送鞭策消息，避免一轮完成后产生两条并行自动链。
11. 新建下一轮后，用户必须仍可从正在运行的新 Tab 输入框右侧的设置菜单取消勾选，以在当前轮完成后停止循环。

## 验收标准

- 新安装或旧状态升级后，总开关为关闭，聊天顶部没有循环控件。
- 循环开关位于 Agent 输入框右侧的设置菜单中；开启后，聊天窗口内必须有醒目的“循环重复已开启”状态提示，并说明完成后会自动重跑。
- 开启总开关并勾选某 Agent 后，正常完成会在同 Pane 新建并激活一个 Tab，首条用户提示已自动发送，Agent 已开始运行。
- 新 Tab 完成后继续生成下一 Tab；在任意运行中的新 Tab 取消勾选后，该轮完成不再生成下一 Tab。
- `background-pending`、停止、错误以及无可复用文本时均不会创建 Tab。
- 延后发送/计划唤醒存在时不抢跑；循环勾选时自动鞭策不另起一条旧 Tab 续写。

## 非目标

- 不复制首条消息中的图片或其他附件。
- 不提供循环次数上限、间隔时间、定时停止或跨 Pane / 跨工作区目标选择。
- 不在应用重启后主动恢复一个已经失去运行进程的“待触发完成事件”；只保存开关状态，后续真实任务完成时再触发。
