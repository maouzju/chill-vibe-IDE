# 自动更新可靠性设计

`checkForUpdate()` 委托可注入网络传输的 `checkForUpdateWithFallback`；生产仍用 Electron `net.fetch`，测试用确定性响应。

1. 先请求 GitHub API；非 2xx、网络异常或格式无效时回退固定仓库 `/releases/latest`。
2. 使用响应最终 URL 的完整稳定版本 tag 确认当前发布，不能从页面内任意链接猜版本（导航和发布说明可能包含其它版本）。拒绝外站、其它仓库和预发布后缀。
3. 已是最新版本时不请求附件。存在新版时先读取内嵌附件；缺少对应平台附件时请求由已验证 tag 构造的 `/releases/expanded_assets/<tag>`。不能采用 HTML 中任意 `src`。
4. 资产只接受 GitHub HTTPS、固定仓库、同一完整 tag 的直接附件 URL；排除外站、源码归档和其它版本附件，去重。不改变下载续传与安装路径白名单。
5. 每个请求含响应体读取均有 15 秒上限；两条路径均失败保留两个原因，无附件保持原有明确错误。

第一实现切片只修复更新检查，保持下载、替换、重启和状态数据不变。回滚仅需还原检查入口及纯函数。

验证：先用接近真实的懒加载 HTML 和模拟 403 请求链复现失败，再实现；最后使用 Electron 的真实网络栈在隐藏、隔离的测试进程里强制首请求返回 403，确认得到最新版本及官方 ZIP URL。测试不触发用户安装目录替换。

- 隐藏、独立 profile 的 Electron 网络探针强制 API 返回 403，实际访问官方 latest 与 expanded_assets，成功得到 v0.20.18 和官方 ZIP 地址。记录在 .chill-vibe/updater-proof/stdout.log。
