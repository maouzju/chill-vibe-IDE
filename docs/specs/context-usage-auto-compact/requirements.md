# 上下文占用显示 + 快满自动压缩 — 需求

## 现状（代码核实，2026-11-12，v0.21.25）

- 会话里没有任何地方显示「当前上下文用了多少」。回合结束时 `done.usage.used` 是**一回合内所有请求之和**
  （pitfall #322），不能当占用；Codex 的 `done` 完全不带用量。
- Chill Vibe 自己没有「快满自动压缩」：`shouldAutoCompactCodexConversation` 写死 `false`，全靠
  Claude / Codex CLI 在回合中途自己压。CLI 压缩发生在回合中间，用户看不到预兆，也调不了阈值。

## 需求

1. **占用指示器**：每张聊天卡的输入框按钮区显示一个小圆环，表示「最近一次请求占了上下文窗口的多少」。
   悬停显示「已用 / 窗口 / 百分比」。占用高时变色。没有数据时不显示。
2. 占用口径 = 最近一次**主线程**模型请求的输入侧 token（含缓存读写）+ 输出 token。子 Agent 的请求不算。
3. 窗口大小只用 CLI 自己报的值（Claude `result.modelUsage[*].contextWindow`、Codex
   `tokenUsage.modelContextWindow`）。不知道窗口时只显示 token 数，不显示百分比（pitfall #293：不维护模型窗口表）。
4. 压缩之后占用视为「未知」，等下一次请求的真实值；不拿压缩摘要的估算值冒充。
5. 重启后能恢复：占用随回合耗时消息一起落盘，重开应用后指示器仍有值。
6. **快满自动压缩**：发送消息前，如果占用 ≥ 阈值，先自动跑一轮 `/compact`，压完再把用户这条消息发出去。
   用户的消息在压缩期间显示在「排队」区，不丢。
7. 设置里有开关（默认开）和阈值（默认 80%，范围 50%–95%）。
8. 压缩失败时，用户的消息照常发出，不卡住；也不会因为这次失败，把正在等这张卡跑完的其他 Agent 提前唤醒
   （用户那条消息马上就要接着跑）。
9. 不会连环压缩：一次自动压缩之后紧跟的那次发送不再触发；压缩后占用没有明显增长（< 窗口的 10%）也不再触发。
10. 自动压缩回合不响完成提示音、不闪任务栏、不标未读、不触发循环发送。手机监工同口径：不把那条 `/compact`
    显示成用户说的话，压缩回合跑完不响铃、不震动、不弹「跑完了」；用户自己敲的 `/compact` 照常显示、照常提醒。
11. 自动压缩进行中用户再发消息：排队等待，不打断压缩；显式「立即发送」仍可打断（deferred-send-queue 需求 14）。
12. 压缩过的卡换 provider，或会话被清后带着历史另开新会话，新会话仍然带着最初的需求：没有归档回查的 provider
    不按压缩边界截断历史。
13. 在设置里改开关或阈值，已经打开的卡片立即按新值显示圆环颜色和悬停说明，与发送前的判定一致。
14. 压缩回合没收尾（例如压缩中途退出应用、重启后选了不恢复）时，不当作已经压过：圆环照常显示，下次发送照常判定。

## 不在范围

- Gemini：CLI 不报窗口大小、也没有 `/compact`，不显示百分比、不自动压缩。
- 鞭策 / 计划唤醒 / 工作流失败唤醒这些**非用户亲手**的发送不触发自动压缩（仍由 CLI 自带压缩兜底）。
- 不改 CLI 自带的回合中途自动压缩。

## 验收

- Claude 真实事件夹具（2026-11-12 实测 CLI 2.1.233）能读出占用、窗口、压缩边界。
- Codex `thread/tokenUsage/updated` 能读出占用和窗口，子线程不串。
- 判定纯函数覆盖：阈值、开关、无会话、斜杠命令、防连环。
- 指示器明暗主题下都可读。
- 需求 8、12、13、14 各有一条先红后绿的回归测试；需求 10 的手机监工部分覆盖请求解析、服务端广播 / 重放、
  历史与预览、手机页脚本四段。
