# 飞书表格粘贴 — 需求

## 背景

用户从飞书表格复制一个区域后，直接粘贴到 Chill Vibe 聊天输入框。当前输入框是稳定的纯文本编辑器，普通文本可以粘贴，但带图片的富文本剪贴板分支只读取已有的 `text/plain`，在部分飞书内容中会丢掉表格文字；HTML 兜底也不足以恢复表格结构。

## 目标

1. **一次粘贴完成**：用户不需要先粘贴文字、再单独上传图片。
2. **文字不丢**：保留飞书表格的行、列和单元格内容；优先使用剪贴板原生纯文本（通常是制表符 + 换行）。
3. **图片不丢**：从剪贴板 HTML 中提取图片并加入现有聊天图片附件流程，支持多张图片。
4. **不破坏中文输入**：继续使用现有 `textarea`，不改成 `contenteditable`。
5. **安全可控**：只接受受支持的图片 MIME 类型和 `data:` / `http(s):` 图片地址；不执行剪贴板 HTML。

## 验收标准

- AC1：飞书表格有 `text/plain` 时，粘贴结果原样保留单元格文字、制表符和换行。
- AC2：剪贴板只有 HTML 或 `text/plain` 为空时，能从 `<table>` / `<tr>` / `<td>` 生成可读的制表符表格文本。
- AC3：表格 HTML 含一张或多张受支持图片时，文字仍插入输入框，同时所有可下载图片都进入附件预览和发送附件列表。
- AC4：复制 Chill Vibe 内部带图片的消息时，文字和内部图片附件同时保留，不因附件分支丢掉文字。
- AC5：损坏 HTML、超大 HTML、不支持的图片地址不会阻止文字粘贴，也不会执行脚本。
- AC6：现有 OS 文件粘贴、图片粘贴、路径粘贴和中文输入行为不回归。
- AC7：剪贴板里同一张图同时有原生图片文件和 `<img>` 时只生成一个附件；HTML 图片多于原生文件（表格带多图）时取抓回的那批，抓取失败退回原生文件。
- AC8：复制便签图片（`text/plain` 只是文件名兜底）粘进聊天框时，保留图片附件，不把文件名插入输入框。
