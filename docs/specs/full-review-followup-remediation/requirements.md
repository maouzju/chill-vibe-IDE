# Requirements — Full Review Follow-up Remediation

## Goal

修复 2026-08-02 全量代码审查中经探针复现的 10 项缺陷（6 高 / 4 中）。优先级排序依据是「用户资产是否会被静默破坏」：提交进错内容、聊天卡片消失、待发送队列丢失、Agent 在错误的工作区继续写文件，都属于用户无法自行察觉、也无法自行恢复的损失。

本轮不做重构、不改视觉、不新增功能，每一项都以最小改动 + 窄回归测试落地。

## Requirements

### 高优先级

1. **Git Agent 策略提交必须限定在真实改动范围内。** AI 返回的 `commits[].paths` 不得被原样执行；提交调用必须携带路径子集，绝不能退化成提交整个 index。模型用 `"."` 之类通配代替逐个列举时，只展开成本次分析范围内的真实改动，不得交给 git 扫描整棵树。全部路径都对不上真实改动时必须显式失败，而不是静默全提交。
2. **重命名文件必须整体处理。** 暂存、取消暂存、按选中文件提交三条路径都要同时覆盖新路径与 `originalPath`，不得把一次 rename 拆成「新增未删除」或「删除 + 未跟踪」两截。
3. **标签移动与关闭必须原子。** 过期 pane ID 下的移动/关闭必须整体回退到原状态，不得出现卡片消失、同一卡片同时存在于两个工作区、或卡片仍开着却已被写入历史归档。
4. **正在运行的卡片跨工作区移动时必须停止旧进程。** 跨列移动会重绑卡片并清掉会话，旧进程不得继续在旧工作区改文件或把回复投递到已不存在的位置。pane ID 过期导致移动被拒绝时，绝不能误停用户仍在跑的 Agent。
5. **关闭工作区时快照必须先于任何破坏性清理落盘。** 停止 Agent 与清空待发送队列都是不可逆副作用，必须排在唯一可能失败的快照保存之后；快照本身要先把在跑的流收尾，避免重开的工作区复活指向死进程的假流。
6. **白噪音生成不得以绕过沙箱的方式运行。** 一个只需要返回 JSON 的功能必须使用受限沙箱与免审批参数，并具备硬超时与输出上限，不得让子进程无限期挂住主进程 IPC 或无界累加内存。

### 中优先级

7. **停止操作不得让改动记录出现在 `done` 之后。** 工作区差异计算的 await 返回后必须重新确认终态；停止必须仍然立即生效，不得因此变慢或挂住。
8. **历史 sidecar 索引失败后必须可恢复。** 同名文件内容被修复后要能重新进入索引并让 phase 回到 complete，且不得让健康目录为此付出额外的全量 stat 开销。
9. **历史提交 diff 必须有字节预算与请求代次校验。** 服务端返回的补丁需要有上限并显式标注截断；快速切换提交时迟到的响应不得覆盖当前选择，也不得提前关闭加载态。
10. **原生会话完成判定只读文件尾部。** 断线恢复判定不得整读数十至数百 MiB 的会话文件；尾部窗口要能按需扩大，被截断的半行必须按「读不到」处理，保持 fail-open 语义。

## Non-goals

- 不重构 Git 工具卡 UI，不改变「不带 paths 提交 = 提交整个 index」这一服务端既有语义（`commitAllGitWorkspace` 依赖它）。
- 不改 `session-fork` 的整文件读取路径：fork 需要从文件头改写到切点并写回完整新文件，与尾读需求正交。
- 不做视觉快照刷新，不改任何主题相关表现。
- 不扩大 provider 并发或恢复策略的行为边界。

## Acceptance

- 每一项都有先失败后通过的窄测试，且全部落在已注册的测试文件中。
- `pnpm test:quality` 通过；各项对应的窄测试文件全绿。
- 既有测试不得为了通过而被削弱；确需调整的断言必须在设计文档中写明理由。
