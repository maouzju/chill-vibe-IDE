# Git 同步冲突交给显式会话 — 需求

## 背景

Git 工具卡点「同步」后，pull 出现合并冲突时，同步面板只显示一行
「检测到冲突，正在调用 Codex 解决...」，Codex 在后台静默跑一个看不见的回合，
跑完自动 push。用户（2026-10-13）明确要求：这件事必须**显式打开一个 Chill Vibe 会话**继续干。

后台静默方式的问题：

- 看不到 Agent 怎么取舍两边改动，也无法中途纠正或补充上下文；
- 出错只剩一行报错，没有可回看的过程；
- 解完立刻自动 push，用户没有任何审视机会。

## 需求

1. 同步流程 pull 后检测到冲突时，不再发起隐藏的后台 Codex 请求。
2. 改为在 Git 卡所在的 pane 新建一个普通会话 tab，并立即切换过去（显式可见）。
3. 新会话自动发出第一条消息：列出冲突文件，要求解决冲突（保留双方有意义的改动、确认无冲突标记）、
   `git add`、完成合并提交，最后 `git push` 完成同步，并汇报每个文件的取舍。
4. 新会话使用设置里的 Git Agent 模型（Codex + 对应档位），与原后台方式同一配置源。
5. Git 卡的同步面板随即收起，以飘字提示「已打开新会话处理冲突」；同步流程本轮结束，不再自动 push。
6. 宿主没有提供开会话的能力时（理论兜底），同步面板留在错误态提示手动解决，绝不在后台偷偷跑或直接 push。

## 不做

- 不改 pull / push 本身、blocked files 确认流程、AI 提交分析流程。
- 不等待新会话结束后再回到 Git 卡自动 push —— push 由会话里的 Agent 在用户眼皮底下完成。
