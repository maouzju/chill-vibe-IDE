# 关闭按钮行为 — 需求

> 2026-08-09 首版只有「关闭后最小化到任务栏」一个布尔开关。
> 2026-08-17 用户反馈「根本没有实现，它只是把窗口缩小了而已」——最小化与点「—」无异，
> 应用仍占着任务栏格位。本文档随之扩展为三态关闭行为。

## 目标

为 Electron 桌面版提供一个可持久化的关闭行为设置，覆盖三种用户期望：正常退出、留在任务栏、
彻底藏起来只留系统托盘图标。后两者都不得中断正在运行的 Agent。

## 功能需求

1. 设置 → 实用中提供「点击关闭按钮时」下拉，三个选项：
   - `quit` 退出应用（默认，等于历史行为）；
   - `minimize` 最小化到任务栏（保留任务栏入口）；
   - `tray` 缩到系统托盘（让出任务栏格位）。
2. 默认 `quit`。旧存档中 `minimizeToTaskbarOnCloseEnabled === true` 必须迁移为 `minimize`，
   其余情况回落 `quit`；非法值同样回落 `quit`。
3. 选 `minimize` 时，点击自定义标题栏关闭按钮或系统窗口关闭按钮：阻止销毁、最小化窗口、
   主进程与后台 Agent 继续运行。
4. 选 `tray` 时，除上述外还要：
   - 隐藏窗口并调用 `setSkipTaskbar(true)`，使任务栏不再保留入口；
   - 在系统通知区创建托盘图标，作为唯一的返回入口；
   - 托盘图标单击/双击恢复窗口，右键菜单提供「显示 Chill Vibe」与「退出」；
   - 托盘菜单的「退出」必须走既有刷盘退出流程，不得丢失未保存状态。
5. 托盘图标资源缺失或创建失败时，必须退回 `minimize`，绝不允许把窗口隐藏成用户叫不回来的进程。
6. 应用明确退出、安装更新等已进入退出流程的场景不得被该设置拦截。
7. 设置变更立即同步给主进程，不要求重启；切换到非 `tray` 时应销毁已存在的托盘图标。
8. 窗口藏在托盘时再次启动应用（single-instance 二次实例）必须恢复窗口与任务栏格位。
9. 进程退出前销毁托盘图标，避免通知区残留幽灵图标。
10. 浏览器模式可以展示并保存该设置，但说明需写明它只影响桌面版。

## 验收标准

- 新安装默认 `quit`；旧存档勾过最小化的升级后为 `minimize`，行为不变。
- 选 `minimize` 点关闭：窗口最小化，任务栏仍有入口，进程与任务不退出。
- 选 `tray` 点关闭：窗口消失、任务栏无入口、通知区出现图标；单击图标窗口回来且任务栏入口恢复。
- 托盘右键「退出」后状态已刷盘，下次启动不丢会话。
- 选 `quit` 点关闭：仍完成既有持久化刷盘并退出。
- 中英文文案完整，设置项在明暗主题下沿用现有下拉样式。
