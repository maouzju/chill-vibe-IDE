# 新会话默认档位 + 「卡上改动只管这一张」开关 — Requirements

2026-11-06 群友反馈（截图）：「chillvibe 改一个窗口的思考等级和模型，需要不影响新开窗口的默认设置。比如我特定任务需要开个高思考度，结果后面都被改了。」

## 现状（代码核实）

- 卡上拧思考档位（旋钮 / 手机远程）会同时写 `settings.modelReasoningEfforts[provider][model]`，之后**所有**新开的该模型会话都用这个档位。
- 卡上换模型（下拉 / 滚轮 / `/model` / 手机远程）会写 `settings.lastModel` 和当前列种子 `column.model`，新开 tab / 新开列跟着走；新 tab 还会继承同 pane 活动卡的模型。
- 设置里**没有**地方直接设默认档位：唯一的入口就是去某张卡上拧，所以「临时开一次高思考」和「改默认」是同一个动作。

## 需求

1. **默认思考档位表**：设置 →「模型与对话」新增一项「默认思考档位」，按 provider 分组列出模型，每个模型一个档位下拉。
   - 列出的模型 = 该 provider 在模型下拉菜单里可见的内置项 + 用户自定义项 + 设置里的默认模型（排第一，标注「默认模型」）。不列工具卡、本地模型条目；Gemini 只有「自动」一档，不列。
   - 下拉选项与卡上旋钮同一份（按模型过滤，Fable 没有「自动」等）。
   - 显示值 = 新开该模型会话时实际会用的档位（与 `getPreferredReasoningEffort` 同一规则）。
   - 改表只影响之后新开的会话，不改已开的卡（pitfall #40 同一口径）。
   - **表只在开关打开时出现**。2026-10-10 用户删过全局「思考深度」下拉，原话「这俩设置实际上已经没啥意义了，去掉吧」——卡上一调就把它覆盖了。开关关着时表同样会被卡上覆盖，没有说了算的份，所以不显示；关着时这一项只剩开关一行。
2. **开关「卡上改的模型和档位只管这一张」**（字段 `pinNewSessionDefaults`，默认关）：
   - 关（现状不变）：卡上换的模型、拧的档位照旧记成新会话的默认。
   - 开：卡上换模型不写 `lastModel` / 列种子；卡上拧档位不写档位表。新开 tab / 新开列的模型一律取设置里该 provider 的默认模型（不再继承旁边那张卡、列种子、`lastModel`），档位取档位表。
   - provider 的选择规则不变（显式指定 > 同 pane 活动对话卡 > `lastModel` > 列 provider）：设置里没有「默认 provider」这个概念，provider 仍随上下文。
   - 显式指定了模型的新建（超管 `create_session`、工具卡、看板）不受影响。
3. 旧存档没有新字段时按「关」升级，任何人的现有行为不变。

## 不在范围

- 看板模板、超管目录、`/model` 的模型列表不吃档位表的列表范围（它们各有来源）；但它们新建会话时取默认档位本就走 `getPreferredReasoningEffort`，自然吃到档位表的值。
- 不新增「默认 provider」设置。

## 验收

- 单测（reducer）：开关开时卡上拧档位不写档位表、卡上换模型不写 `lastModel`/列种子、新 tab / 新列取设置默认模型与档位表档位；开关关时维持现状；设置表的写入 action 不受开关影响；归一化缺字段为 false。
- 单测：档位表的模型清单（默认模型置顶、关掉的项不列、自定义项列入、Gemini 不列）。
- 视觉快照：设置「默认思考档位」项 light / dark（开关开）；关掉开关后表收起。
