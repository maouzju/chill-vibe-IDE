# Requirements — 右键删除历史会话

## 背景

会话历史下拉（`会话历史` 标签页）里只能恢复归档会话，无法删除。用户过去只能靠恢复后再关闭来间接清掉一条，
而真正占空间的 `session-history/<entryId>.json` sidecar 从来不会被回收（2026-08-06 现场实测 8,863 个 sidecar 约 974MB）。

## 用户故事

- 作为用户，我在历史会话列表里**右键**某一条，可以直接删除它，这样过期或误归档的会话不再占据列表与磁盘。

## 验收标准

1. 在「会话历史」标签页里右键任意一条历史条目，弹出上下文菜单，其中包含「删除此会话历史 / Delete this session」项。
2. 右键**不得**触发原有的「恢复该会话」行为（现有恢复走 `mousedown` + 左键判定）。
3. 选择删除后弹出二次确认（与文件树删除一致的 `window.confirm` 惯例）；取消则什么都不做。
4. 确认后：
   - 该条目立即从列表消失（本地 `state.sessionHistory` 与深搜结果 `catalogSessions` 同时移除）；
   - 磁盘上的 `session-history/<base64url(entryId)>.json` sidecar 被删除；
   - 该条目被写入 `catalog-hidden.json` 隐藏名单，保证 catalog 索引/分段摘要中的残留不会让它复活；
   - 删除结果被持久化，重启后不再出现。
5. 外部历史（`外部历史` 标签页，来自 `~/.codex` / `~/.claude` 的原始会话文件）**不提供删除**——那是其它工具的数据，本功能不碰。
6. 删除失败（文件被占用等）不得让菜单卡住或让 UI 崩溃；条目仍从列表移除，错误只记录到控制台。
7. 明暗两套主题下，上下文菜单的默认/悬停/危险项样式都可读。

## 非目标

- 批量删除、按时间清理、回收站或撤销。
- 删除外部 provider 的原始会话文件。
- 改动归档写入路径本身。
