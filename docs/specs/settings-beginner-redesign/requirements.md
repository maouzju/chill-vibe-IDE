# Requirements: 设置面板新手友好重构

## Goal

- 让第一次装 Chill Vibe 的人在 3 分钟内完成「装 CLI → 连账号 → 选模型」，而不用先读懂「路由 / 代理 / 沙箱策略」这些词。
- 设置面板从「九张卡片瀑布流」改成「左侧分类导航 + 右侧单列」，一次只看一类；默认只露基础项，高级项折叠。
- 设置面板不再承担教学：教学交给首启向导；面板只负责「看状态、改配置、一键修」。

## User Stories

- 作为新手，我打开设置就能看到三盏灯（CLI 装好没 / 账号能用没 / 版本兼容没），红灯旁边有一个按钮点了就修，不用去翻文档。
- 作为新手，我第一次打开应用会被一个 3 步向导带着走：装 CLI、连账号（导入 cc-switch 或直接填 API key）、选默认模型；每步都能「暂时跳过」。
- 作为新手，我在搜索框输「代理」或「proxy」都能找到断线重连那一项，并且它旁边有一句人话解释「做什么；拿不准就保持默认」。
- 作为老用户，我原来能改的每一个开关都还在，只是搬进了六个分类的「高级设置」里；接口（Routing）页依旧可用。
- 作为维护者，分类归属 / 搜索过滤 / 健康灯判定 / 向导步进都是纯函数，能用 Node 测试钉住。

## Acceptance Criteria

- [ ] AC1 设置面板抽到 `src/components/settings/` 下的独立组件；`App.tsx` 里那份 `showLegacySettingsPanel && (...)` 死代码（约 750 行重复 JSX）删除。
- [ ] AC2 六个分类：开始使用 / 模型与对话 / 外观与编辑 / 自动化与工具 / 网络与安全 / 系统；左侧导航，右侧单列，只渲染当前分类。原「接口」页里的 provider 配置、cc-switch 导入、断线重连代理在这些分类里都能找到；「接口」顶部 tab 保留不动。
- [ ] AC3 基础 / 高级分层：基础项只有语言+主题、连接账号、默认模型、检查更新；其余全部在各分类的「高级设置」折叠区里，默认收起。不新增持久化字段（折叠状态只活在内存）。
- [ ] AC4 首启向导 3 步：装 CLI → 连账号 → 选模型；复用现有环境检测 / 自动安装 / cc-switch 导入；连账号一步还能直接填 API key；每一步都可跳过；完成后写 `chill-vibe:onboarding:v1 = done`（与现状一致）。
- [ ] AC5 设置内容区顶部常驻「环境健康」卡：CLI 已安装 / 账号可用 / 版本兼容 三盏灯，每盏灯在非绿时给一个一键修复按钮（分别复用：一键安装环境、跳到账号项、下载/切换兼容版 CLI）。
- [ ] AC6 搜索框跨分类过滤：匹配标签、人话说明、关键词，中英文都命中；有搜索词时忽略分类与折叠，平铺显示命中项并标注所属分类。
- [ ] AC7 术语项（Codex 安全策略、代理 / 断线重连、思考深度、路由、兼容版 CLI、隔离 HOME 等）都有一句人话提示：「做什么；拿不准就保持默认」。
- [ ] AC8 实验功能与危险操作永远排在「系统」分类最底部，顶部有醒目的「一般不用动 / Usually leave as is」标签；实验项带「实验」标签；「清空本地数据」是最后一项。
- [ ] AC9 所有新增文案中英双语；浅色 / 深色主题都检查过。
- [ ] AC10 纯逻辑（分类归属、搜索过滤、健康灯判定、向导步进）有 Node 单测，先红后绿。

## Non-goals

- 不改任何设置项的语义或默认值；不新增 `shared/schema.ts` 字段。
- 不删除「接口」顶部 tab（用户可能已习惯）；只是让同一批控件也能从设置分类里到达。
- 不做设置项的拖拽排序 / 自定义分类。
