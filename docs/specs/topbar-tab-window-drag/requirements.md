# 顶栏标签按住拖动窗口 — 需求

> 2026-09-11 用户截图报告：自定义标题栏左上角的「Chill Vibe / 接口 / 设置」三个标签，
> 按住拖不动窗口。这三个标签占了标题栏最显眼的一段，用户直觉上把它当标题栏用。

## 背景

Windows / Linux 走无边框窗口（`electron/window-options.ts`），顶栏整体是
`-webkit-app-region: drag`，但顶栏上所有可点击控件（标签、加列、停靠列、远程监工、
窗口控制按钮）都标成 `no-drag`。标成 `drag` 的元素在 Windows 上由系统接管
（`WM_NCHITTEST` 返回 `HTCAPTION`），DOM 收不到 `mousedown`/`click`，所以
「把标签改成 drag」会让标签再也点不动。要同时满足「点一下切换」与「按住拖窗口」，
必须由渲染层自己识别手势，再请主进程移动窗口。

## 功能需求

1. 在自定义窗框（win32 / linux）下，鼠标在顶栏标签上按下并移动超过阈值（4 CSS px）
   时，窗口跟随光标移动；松开即停。
2. 按下后未超过阈值就松开，仍然是一次普通点击：切换到对应标签。
3. 一次拖动手势结束后，紧随其后的 `click` 必须被吞掉，拖完不能顺带切换标签。
4. 拖动期间窗口位置与光标的相对偏移保持恒定（按住哪一点，那一点始终在光标下）。
5. 最大化状态下开始拖动：先还原窗口，再把窗口放到光标下，光标在窗口内的横向比例与
   最大化时一致（镜像 Windows 原生标题栏行为）。
6. 最小化、全屏、不可见窗口不响应拖动。
7. 键盘、触摸与非主键（右键/中键）不触发拖动；只有主键指针才算。
8. 渲染进程失联（拖动中未再发消息）时，主进程在 3 秒内自动结束该次拖动，不允许留下
   一个永远跟随光标的窗口。
9. macOS 与浏览器模式不启用：前者用系统 `hiddenInset` 标题栏，后者没有窗口。
10. 标签仍保持 `app-region: no-drag`（既有 `tests/github-shell.spec.ts` 断言不变），
    顶栏其他空白区域的原生拖拽不受影响。
11. 拖动中按住鼠标暂停超过 3 秒后，继续移动仍须跟随；正常暂停不能被当作渲染进程失联。

## 验收标准

- Windows 打包版：在「接口」标签上按住拖动，窗口跟着走；松开后活动标签不变。
- 单击「接口」仍切到接口面板；单击后不残留任何拖动状态。
- 最大化时在标签上拖动：窗口还原并跟随光标。
- 双主题下标签外观无变化（本需求不改样式）。
- Node 测试覆盖：主进程拖动几何纯函数、渲染侧手势状态机、桥接 API；
  Playwright 覆盖：拖动手势调用桥接且不切换标签，单击仍切换。
