# 工作区列停靠到顶栏（Workspace Column Dock）— 需求

## 背景

看板是横向排列的多个工作区列（`.workspace-column`）。项目一多，列就把水平空间挤满；用户想临时把某一列"收起来"，但又不想走"关闭工作区"（那会停掉任务、把会话归档进历史），只想把它从看板上暂时挪开，随时再拿回来。

用户原话（2026-09-10）：

> 我希望 IDE 的项目列能拖到窗口最上方收起，再次点击就是再出现在下方的工作列。

截图里红圈位置就是顶栏（`.app-topbar`）左侧、看板页签右边的空白区。

## 用户故事

1. 作为用户，我把一列的标题（`.column-headline`）拖到窗口顶栏，松手后这一列从看板消失，顶栏出现一个带项目名的小标签。
2. 作为用户，我点击顶栏上的那个小标签，这一列回到看板，回到它被收起前的位置（相对其他列的顺序不变），标签消失。
3. 作为用户，收起的列里正在跑的任务、草稿、会话、tab 布局一个都不能丢；收起只是"不显示"，不是"关闭"。
4. 作为用户，重启应用后，被收起的列仍然是收起状态，顶栏标签还在。
5. 作为用户，开始拖一列时我要能一眼看出顶栏是可以放的地方；没有在拖列的时候顶栏不应多出任何东西（ui-principles 规则 3：闲置时 chrome 必须退场）。

## 验收标准

- [x] `BoardColumn` 新增可选布尔字段 `docked`；缺字段的旧存档解析后等价于未停靠。
- [x] reducer 提供 `dockColumn` / `undockColumn`；对不存在的列或已处于目标状态的列返回原 state 引用（不触发持久化）。
- [x] 停靠不改变 `columns` 数组顺序；恢复后列出现在原位置。
- [x] 看板只渲染 `docked !== true` 的列；停靠列不参与列宽拖拽的 DOM 兄弟遍历（它不在 DOM 里即可）。
- [x] 顶栏在"新增工作区"按钮右侧按 `columns` 顺序渲染停靠标签，文案为工作区路径末段（无路径时用列标题），`title` 显示完整路径；点击即恢复。
- [x] 拖动一列期间，顶栏出现一个明确的停靠落区；拖到落区上有 `is-over` 反馈；松手即停靠。拖拽结束（drop / dragend / 丢失 dragend 的看门狗）后落区消失。
- [x] 顶栏标签与落区都是 `app-region: no-drag`（自定义窗框下顶栏本身是窗口拖拽区）。
- [x] 亮/暗两套主题下，标签的默认 / hover / focus 状态与落区的默认 / is-over 状态都只用 `src/index.css` 的共享 token。
- [x] 单测覆盖 reducer 两个 action 与 schema 兼容；Playwright 覆盖"停靠标签可见 → 点击恢复"与"拖列到落区 → 停靠"。

## 增补（2026-09-10）：停靠标签的状态提示

首版的"不做状态徽标"非目标已被用户推翻：

> 收起到上方的项目 也要有是否正在运行的橙色呼吸光效以及有新结果的时候的蓝点

列被收起后就不在看板上，跑没跑完只能靠拖回来看 —— 顶栏 chip 是它唯一的可见代表。

- [x] 列内任一卡片 `status === 'streaming'` 时，chip 显示橙色呼吸边框（复用 `--warn` / `--stream-border-glow`，与卡片、页签的"橙 = 在跑"一致）。
- [x] 列内任一卡片 `unread` 或 `completionGlow` 时，chip 末尾显示蓝点（复用 `--accent`，与 `.card-unread-dot` / `.pane-tab-status.is-unread` 一致）。
- [x] 两者互相独立，可同时出现（一张卡在跑、另一张已跑完没看）。
- [x] 状态同时进入 `title` 与 `aria-label`，不做纯颜色编码。
- [x] 停靠列不参与"活动 tab 自动已读"，否则蓝点会立刻自己消失。
- [x] 呼吸动画必须登记进 `tests/idle-animation-budget.test.ts` 的 allowlist 并写明理由（基数受限于顶栏，不随 pane 数或会话时长增长）。
- [x] `prefers-reduced-motion` 下停用动画，改用静态强边框。

## 非目标

- 不做把顶栏标签再拖回看板指定位置（点击恢复到原位已足够）。
- 不改远程监工（手机端）对列的呈现；手机端仍能看到停靠列。
- 自动化看板 / 超管往停靠列里新建会话时不自动恢复该列。这是已知取舍，见 design.md。
