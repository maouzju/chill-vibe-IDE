# 工作区重开恢复标签页 — 设计

## 存储

- 新增 `closed-workspaces/` sidecar 目录。
- 文件名使用规范化工作区路径的 SHA-256，避免 Windows 路径字符和文件名长度问题。
- 每个工作区只保留最近一次快照：`closeId`、`closedAt` 和经过现有持久化压缩/归一化的
  `BoardColumn`。
- 主 `state.json` 不增加整列快照字段。

## 关闭流程

1. 停止该列流任务并清理未发送队列。
2. 生成 `closeId`，原子写入关闭工作区 sidecar。
3. reducer 移除列；归档聊天时把同一个 `closeId` 写入对应历史条目。
4. sidecar 写入失败时不移除工作区，避免用户以为可恢复但实际丢失精确标签状态。

## 重开流程

1. 路径只在输入提交、文件夹选择或“最近工作区”点击时提交，不在每个按键时改全局状态。
2. 仅当目标列是单个未使用空聊天、且没有其他列打开同一路径时尝试恢复。
3. 有精确快照时，用快照替换目标占位列的内容，保留目标列 id 和当前宽度；随后删除
   `sessionHistory.workspaceCloseId === closeId` 的重复历史条目。
4. 没有 sidecar 时，从同工作区最新、时间紧邻的一批历史条目推断旧版关闭批次，加载正文后
   恢复为单 pane 聊天标签。
5. 普通“修改已有列路径”仍走原更新逻辑，不覆盖现有标签。

## 安全与兼容

- sidecar 加载复用 `state-store` 的列归一化和消息压缩边界。
- 恢复时卡片不重新挂接已停止的流；provider 原生会话 id 可继续用于后续对话。
- 当另一个列仍使用旧路径时，修改占位列路径不得把旧路径的全部历史错误迁移到新路径。
- 重置状态删除 `closed-workspaces/`。

## 验证

- reducer 红测：精确快照替换占位列、清理同批历史；旧历史批次恢复；共享旧路径时不错误迁移历史。
- state-store 红测：精确 sidecar 往返；缺 sidecar 时返回最新旧版批次；重置清理 sidecar。
- 通过定向 Node 测试、`pnpm test:quality`、Windows Electron 打包。
