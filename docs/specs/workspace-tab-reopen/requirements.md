# 工作区重开恢复标签页 — 需求

## 背景

关闭工作区列时，当前实现只把有内容的聊天归档到“历史会话”。用户再次选择同一工作区时，
只会把新空列的路径改回去，不会恢复关闭前的标签页、分栏和当前激活页。

## 需求

1. 关闭有路径的工作区前，保存该列最后一次可恢复快照。
2. 在一个未使用的新列中重新选择该工作区时，自动恢复：
   - 标签页及顺序；
   - pane 分栏、比例和激活标签；
   - 聊天、草稿和工具标签的持久化状态。
3. 恢复不得覆盖一个已经有真实内容的列，也不得在同一路径仍有其他打开列时自动复制旧快照。
4. 关闭时已有的行为保持不变：运行任务先停止，未发送队列取消，有内容的聊天进入历史会话。
5. 精确快照恢复后，关闭动作生成的那批历史副本应从历史索引移除，避免同一会话重复出现。
6. 升级前已经关闭、尚无精确快照的工作区，重开时应尽量恢复最近一次批量归档的聊天标签。
7. 快照正文放在独立 sidecar 中，不塞进主 `state.json`，避免让普通保存和启动 IPC 变重。
8. 清空应用状态时必须一并清除关闭工作区快照，不能在重置后再次复活旧标签。

## 非目标

- 不恢复关闭时仍在运行的进程；重开后的卡片保持停止后的可继续状态。
- 不把旧版本历史推断成原始多 pane 布局；旧数据只能尽力恢复聊天标签。
